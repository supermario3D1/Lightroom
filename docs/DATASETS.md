# Data strategy

Kestrel's quality comes from measurement and calibration, not from scraping photographs. This document states
exactly which data exists, where it came from and what it is allowed to do.

## Principles

1. **No training on photographs we do not have rights to.** Not scraped, not "publicly available", not
   research-only.
2. **Consent is explicit and revocable.** A photographer who lets their frames calibrate a genre can withdraw, and
   the derived parameters are removed at the next release.
3. **Customer photographs are never training data.** There is no code path from a customer library to a shared
   model. Personalisation only moves bounded preference numbers locally.
4. **No personal data in calibration sets.** No faces are retained; frames are reduced to statistics (luminance
   distributions, skin samples, colour histograms, noise estimates) before they inform anything.
5. **Provenance is recorded.** Every calibration reference has a note in this file: who, what rights, what it
   informed.

## What exists in the repository

| Asset | Path | Rights | Used for |
|---|---|---|---|
| `football_night.jpg` | `assets/samples/` | supplied by the product owner for this project | demo library, evaluation harness baseline, README before/after |
| Synthetic scenes | generated by tests | none needed | unit tests: night cue, sky, court false positives, thin-margin guardrails |
| `data/inbox/study.json` | *not committed* | user-supplied study frames | local parameter study; statistics only |

The ten study frames used to calibrate the sports profile were supplied by the user for this project. They are
**not** in the repository (they live in the gitignored `data/` folder) and are represented only by the statistics
in `docs/SPORTS_REFERENCE.md`.

## Calibration workflow

```
reference frames (permission documented)
        │
        ▼  measurement only — no pixel retention
statistics: median luma, p95, face/subject luminance, K, tint, saturation, noise
        │
        ▼
target ranges per genre  ──►  decision/recipes.py GENRE_BASE
        │
        ▼
evaluation harness on held-out frames  ──►  accept / reject the change
```

Nothing in this loop stores or transmits a photograph. The calibration step reduces each frame to a row of numbers.

## Evaluation sets

| Set | Size | Purpose | Held out? |
|---|---|---|---|
| Night football | 1 | sports baseline | no — used in CI |
| User study frames | 10 | genre and target calibration | partially |
| Synthetic scenes | 12 | guardrails and false-positive tests | never used for tuning |
| Community references (ranges only) | — | sanity checks on target ranges | n/a |

A release must not regress the harness median by more than 0.01 on any set. When a change improves one genre and
worsens another, both numbers go in the changelog.

## What we would need to do more

To train a segmentation or denoise network properly we would need:

- a large, licensed sports dataset with permissive terms (or a licensing budget);
- annotation staff and a review process;
- an evaluation protocol that separates "looks better" from "measures better";
- a clear statement in the product about what the model was trained on.

That is a different company. The current architecture is designed so that adding such a model later is a slot, not
a rewrite — and so that its absence is visible rather than hidden.
